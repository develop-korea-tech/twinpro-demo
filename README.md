# TWIN PRO 운영 모니터링 시연 서버 (Supabase)

조선 블록 제작 운영 모니터링 시연 시스템입니다. 화면 5개(01H 확정안)와 Supabase(Postgres) 서버 함수로 구성되어 있으며, 받은 엑셀(`02 가상데이터.xlsx`) 15개 시트를 그대로 DB에 올려 사용합니다.

- 화면 주소: **https://develop-korea-tech.github.io/twinpro-demo/** (GitHub Pages, 저장소 develop-korea-tech/twinpro-demo)
- 화면 파일: `twinpro.html` 한 파일. 더블클릭해도 같은 서버에 붙습니다.
- 서버: Supabase 프로젝트 `twinpro-demo`(서울 리전). 테이블 23개, 화면에서 부르는 서버 함수(RPC) 16개, 뷰 2개, Edge Function 1개(AI 요약)로 구성됩니다.
  - 주소: `https://rrgvqgphhwzkeuvdwndu.supabase.co` (완성 파일 `twinpro.html`에 이미 들어 있습니다)
  - 시연 코드: 팀 단톡방에서 따로 공유합니다.
- 기준시점: 2026-09-16(수) 12:00. 시연 시계는 [+10분] 버튼으로만 진행되며 16:00에 멈춥니다.

## 2. 실행 방법 (이미 설치된 서버에 붙을 때)

1. `twinpro.html`을 더블클릭해 크롬으로 엽니다.
2. 완성 파일에는 서버 주소가 들어 있어 바로 연결됩니다. 다른 Supabase에 붙일 때만 **서버 연결 설정** 화면이 나오며, Project URL과 anon 키를 넣으면 됩니다.
3. 처음 열면 **쉬운 화면**이 나옵니다. 처음 보는 사람용 화면으로, 세 칸을 왼쪽에서 오른쪽으로 읽으면 됩니다.
   - **① 공장:** 블록이 거치는 6단계(자르기 → 붙이기 → 용접 → 검사 → 칠하기 → 옮기기)와 단계별 진행 막대가 보입니다. 멈춘 단계는 빨강·주황으로 표시됩니다. 아래 [▶ 가상 시간 진행]을 누르면 4초마다 5분씩 시간이 흐르고 막대가 차오릅니다(12:00 → 16:00).
   - **② 문제 처리:** 지금 멈춘 문제 하나를 한 문장으로 보여 주고, 처리 순서 4단계(조치 기록 → 사건 해소 → 설비 복구 → 작업 재개)를 표시합니다. 큰 버튼 [다음: ○○ ›]을 누를 때마다 한 단계씩 진행됩니다. 끝나면 [다음 문제 보기 ›]로 다음 문제(자재 대기·검사 불합격)로 넘어갑니다.
   - **③ 결과:** 작업 중인 기계, 고장 난 기계, 오늘 끝난 작업, 해결 안 된 문제 4개 숫자를 막대로 보여 줍니다. ①·②에서 바뀐 숫자는 주황 테두리로 강조되고, "방금 바뀜: 고장 난 기계 1 → 0"처럼 한 줄로 알려 줍니다.
   - [자세히 보기 (관리자 화면) ›]를 누르면 기존 관제 대시보드(5개 화면)로 갑니다. 대시보드 헤더의 [← 쉬운 화면]으로 돌아옵니다. 주소 끝에 `#dash`를 붙여 열면 바로 대시보드가 열리고, 새로고침해도 보던 화면이 유지됩니다.
   - 시연 코드가 없으면 ①·②의 버튼은 **체험**으로 동작합니다(저장 안 됨, 아래 설명). 코드를 넣은 상태면 실제로 저장되어 모든 사람 화면이 바뀝니다.
   - 관리자 화면의 [? 안내]를 누르면 짧은 안내 창이 열립니다.
   - **체험 모드:** 시연 코드가 없어도 처리 안내의 4단계(조치 기록 → 사건 해소 → 설비 복구 → 작업 재개)를 눌러 볼 수 있습니다. 서버가 실제 규칙으로 처리한 결과를 화면에 보여 주지만 **저장하지 않고 바로 되돌립니다**(`tp_try_steps`). 체험 중에는 화면 위에 노란 띠 "🧪 체험 중"이 뜨고, 다른 사람 화면은 바뀌지 않습니다. [체험 끝내기 (원래대로)]를 누르면 실제 서버 상태로 돌아갑니다.
   - **내 화면만 시간 진행:** 시연 코드가 없으면 헤더 버튼이 [▶ 가상 시간 진행 (내 화면만)]으로 보입니다. 누르면 4초마다 5분씩 내 화면에서만 시간이 흐르고, 가동 중인 공정의 진행률이 오릅니다. 원리는 체험 모드와 같습니다. 화면이 '자동 재생 1회(tick)'를 단계 목록에 쌓아 `tp_try_steps`로 보내면, 서버가 시계 +5분과 생산 카운트 신호를 실제 규칙으로 실행한 뒤 결과만 돌려주고 되돌립니다. 재생 중에 고장 처리 체험을 해도 흐른 시간은 유지됩니다. 16:00이 되면 멈추고, [↺ 처음부터 다시 보기] 또는 [체험 끝내기]로 처음 상태로 돌아갑니다. 다른 사람이 코드로 재생 중일 때는 서버 시간이 이미 흐르므로 이 버튼이 꺼집니다.
4. 관제 대시보드 맨 위의 **문제 카드**가 지금 가장 중요한 문제를 한 문장으로 보여 줍니다(예: "블록 용접 설비 고장으로 작업이 멈췄습니다"). 왼쪽 아래 상자에 `Supabase Postgres · 실시간 연결`이 보이면 서버에 연결된 것입니다.
5. 처음에는 **읽기 전용**입니다. 오른쪽 위 [읽기 전용 · 조작 권한 받기]를 누르고 팀에서 공유한 시연 코드를 넣으면 `🔑 조작 가능`으로 바뀝니다. 해커톤이 끝나면 아래 '보안'의 방법으로 코드를 바꿔 쓰기를 막으세요.
   - 보기만 하는 사람(심사위원 화면, 두 번째 모니터)은 코드 없이 열어 두면 됩니다. 다른 PC에서 조작하면 이 화면도 자동으로 바뀌고, 헤더의 `👥 함께 보는 시연` 표시가 잠깐 `다른 화면에서 변경됨`으로 바뀝니다.
6. **자동 재생은 한 화면만** 할 수 있습니다. 누군가 재생 중이면 다른 화면의 버튼은 `다른 화면에서 시간 진행 중`으로 잠깁니다(재생 화면이 멈추거나 닫히면 15초 안에 풀림).
7. 16:00에 도달하면 재생 버튼이 **[↺ 처음부터 다시 보기]**로 바뀝니다. 두 번 누르면 12:00 원본으로 돌아갑니다. 중간에 되돌리고 싶을 때는 **기준정보** 화면 위쪽 **관리 → [데이터 초기화]**를 두 번 누릅니다.

### 2-1. 확장 기능 켜기 (처음 한 번)

AI 운영 요약·가상 설비 신호·실적 가져오기는 아래 두 가지를 해야 동작합니다. 하지 않아도 기존 화면은 그대로 열립니다.

1. **확장 SQL 실행**
   1. Supabase 대시보드 → `twinpro-demo` 프로젝트 → 왼쪽 메뉴 **SQL Editor** → **New query**를 엽니다.
   2. `supabase_step3.sql` 내용 전체를 붙여 넣고 **Run**을 누릅니다.
   3. `Success. No rows returned`가 나오면 성공입니다.
2. **Claude API 키 등록** (AI 운영 요약에만 필요)
   1. https://console.anthropic.com → **API Keys** → **Create Key**로 키를 만듭니다. 키는 한 번만 보이니 바로 복사합니다.
   2. Supabase 대시보드 → **Edge Functions** → **Secrets**(또는 Project Settings → Edge Functions)로 갑니다.
   3. Name에 `ANTHROPIC_API_KEY`, Value에 복사한 키를 넣고 저장합니다.
   4. 키는 Supabase 서버에만 저장됩니다. 화면 파일이나 GitHub 저장소에는 들어가지 않습니다.
3. 화면을 새로고침합니다. 관제 대시보드 오른쪽 아래 **운영 요약** 패널에 [✦ AI 요약 생성 · 오늘 5/5] 버튼이 보이면 준비된 것입니다.

### 3-2. 3D 확장 데모 (선택, 약 1분)

과제 정의서에서 3D는 **제외범위**입니다. 센터장님께 확인한 결과 "제외범위는 확정이지만, 팀에서 구현 가능하면 일부를 시연 구현하는 것은 문제없음"이라는 답을 받아, 기존 2D 화면은 그대로 두고 **별도 화면**으로 만들었습니다. 화면 위쪽에 "확장 데모 · 과제 제외범위를 팀이 시연용으로 구현"이라고 표시됩니다.

1. 쉬운 화면 오른쪽 위 [3D로 보기 (확장 데모) ›] 또는 ① 공장 칸의 [3D로 보기 ›]를 누릅니다. 주소 끝에 `#3d`를 붙여 열어도 됩니다.
2. 처음에는 3D 모델(약 3MB)을 내려받느라 몇 초 걸립니다. **인터넷 연결이 필요합니다**(3D 라이브러리 Three.js를 인터넷에서 불러옴).
3. 화면 구성
   - 도로를 따라 공정 6곳(01 강재 적치·절단 → 02 판넬 라인 → 03 블록 조립 공장 → 04 검사장 → 05 도장 공장 → 06 블록 운반차)이 있고, 뒤쪽에는 선박을 건조 중인 도크와 골리앗 크레인이 있습니다.
   - 공정마다 떠 있는 라벨과 바닥 링, 경광등 색이 **서버 데이터 그대로** 바뀝니다. 초록 = 작업 중, 빨강(깜빡임) = 고장, 주황 = 멈춤·대기, 파랑 = 오늘 몫 끝남.
   - 왼쪽 패널의 [▶ 가상 시간 진행]을 누르면 작업 중인 곳의 크레인·갠트리가 움직이고, 용접 공장에서 불꽃이 튑니다.
   - 왼쪽 패널 아래의 [다음: 조치 기록 ›] 버튼으로 쉬운 화면과 똑같이 고장을 처리할 수 있습니다. 처리하면 빨간 경광등이 바로 바뀝니다.
   - 라벨이나 공정을 누르면 오른쪽에 블록·진행률·기계·작업지시가 나옵니다. 마우스 드래그로 회전, 휠로 확대합니다.
4. 시연 코드가 없으면 쉬운 화면과 같이 **체험**(저장 안 됨)으로 동작합니다.

**3D 모델을 만든 방법:** 외부 모델·텍스처를 쓰지 않고 Blender(무료)의 Python 스크립트로 크레인·공장·블록을 하나씩 코드로 만들었습니다(`twin3d/scene.py`). 저작권·라이선스 문제가 없고, 숫자를 바꿔 다시 만들 수 있습니다. 다시 만드는 방법은 '6. 수정·재빌드'에 있습니다.

- **AI 요약은 하루 5회**(전체 합산, 한국 시간 0시 초기화)입니다. 리허설에서도 줄어드니 발표 당일에는 아껴 쓰세요. 다 쓰면 버튼이 비활성되고 규칙 기반 요약이 그대로 보입니다.
- AI 요약을 만든 뒤 시각이 바뀌거나 조작을 하면 "이후 변경 있음"이 표시됩니다. 다시 생성하면 최신이 됩니다.
- 자동 재생은 누른 화면(탭)에서만 돌고, 그동안 다른 화면은 재생을 시작할 수 없습니다. 탭을 닫거나 16:00이 되면 멈춥니다.

시연이 끝나면 **기준정보 → 관리 → [데이터 초기화]**를 두 번 누릅니다(16:00이면 헤더의 [↺ 처음부터 다시 보기]). 09/16 12:00 원본으로 돌아갑니다. 서버가 하나라서 초기화하면 **같은 서버를 보고 있는 모든 화면**이 함께 되돌아갑니다. 팀원이 연습 중일 때는 미리 알리고 누르세요.

## 4. 작동 원리

```
[브라우저: twinpro.html]                         [Supabase]
  ① 처음 열 때 tp_ 테이블 18개를 SELECT  ───────▶  Postgres (RLS: 읽기만 허용)
  ② 화면 5개를 같은 상태(S)로 계산
  ③ 버튼 → 서버 함수 호출(RPC) ────────────────▶  규칙 검사 → 저장 → 이력·설비구간 기록
                                                    (한 트랜잭션, 실패 시 전부 취소)
  ④ 실시간 구독 ◀──────────────────────────────  변경 알림(Realtime)
  ⑤ 0.25초 뒤 다시 읽고 다시 그림 (모든 열린 화면)
```

- 상태를 바꾸는 규칙은 전부 서버 함수에 있습니다. 화면은 계산과 표시만 합니다. 그래서 PC 두 대에서 동시에 눌러도 서버가 한 번에 하나씩 처리하고, 규칙을 어기는 요청은 거부합니다.
- 화면 KPI와 같은 값을 서버 뷰(`tp_v_kpi`, `tp_v_occupancy`)로도 계산합니다. 자동 테스트에서 매 단계 두 값이 같은지 비교합니다.

### 상태 체계 (엑셀 `status_codes` 그대로)

| 구분 | 코드 → 화면 표시 |
|---|---|
| 설비 | RUNNING 가동 / IDLE 대기 / FAULT 고장 / MAINTENANCE 점검 |
| 작업지시 | PLANNED 계획 / IN_PROGRESS 진행 / BLOCKED 보류 / COMPLETED 완료 |
| 사건 | OPEN 미해소 / RESOLVED 해소 |

### 서버 규칙 (RPC)

| 함수 | 규칙 |
|---|---|
| `tp_register_fault` (R1) | 설비 고장 등록: 사건 생성, 그 설비의 진행 중 작업 전부 보류, 이미 고장이면 거부 |
| `tp_record_action` (R2) | 조치 기록: 이력만 추가, 상태 변화 없음 |
| `tp_resolve_incident` (R3) | 해소: 조치 기록 1건 이상 필요. 설비·작업 상태는 그대로. 품질 사건은 재검사 합격 차수 1건 추가 |
| `tp_restore_equipment` (R4) | 설비 복구(고장 → 대기): 그 설비의 미해소 고장 사건이 있으면 거부 |
| `tp_resume_work` (R5) | 시작·재개: 보류 사유 미해소, 설비 고장·점검, 같은 설비 다른 작업 진행 중, 선행 작업 미완료면 거부 |
| `tp_hold_work` | 보류: 사유(미해소 사건 또는 메모) 필요 |
| `tp_record_progress` (R6) | 실적: 0 ≤ 인정수량 ≤ 계획수량, 줄일 수 없음. 계획 도달 + 관련 미해소 사건 없음 → 완료, 설비 대기 |
| `tp_change_equipment` (R7) | 설비 변경: 같은 공정 설비만, 고장·점검 설비 불가, 진행 중이면 대상 설비가 비어 있어야 함 |
| `tp_save_work_order` | 작업 관리 [저장]: 설비 변경 → 상태 전이 → 실적 → 메모를 한 트랜잭션으로 처리 |
| `tp_advance_clock` | 시연 시계 +분 (16:00까지) |
| `tp_rename_process` | 공정명 변경 (모든 화면 반영) |
| `tp_reset_demo` | 엑셀 원본으로 초기화 |
| `tp_check_code` | 시연 코드 확인 |
| `tp_ingest_signal` | 가상 설비 신호 입구. RUN(가동)→R5, STOP(정지)→보류, COUNT(생산 카운트)→R6, FAULT(이상 정지)→R1을 그대로 거칩니다. 받은 신호는 결과와 함께 `tp_signal_log`에 남습니다 |
| `tp_try_steps` | 체험 모드: 처리 안내 단계(act·resolve·restore·resume)와 시간 진행(tick, 최대 60단계)을 코드 없이 실제 규칙으로 실행 → 결과 행을 돌려주고 전부 되돌림(저장 안 됨). 이 함수 안에서만 시연 코드 검사를 통과시킴 |
| `tp_sim_claim` / `tp_sim_release` | 자동 재생 잠금: 한 화면만 재생. 재생 중인 화면이 4초마다 잠금을 15초씩 연장하고, 멈추면 놓음 |
| `tp_import_progress` | 실적 가져오기: 행마다 R6 검사, 한 행이라도 거부되면 전체 취소(최대 200행) |
| Edge Function `tp-ai-summary` | AI 운영 요약: 시연 코드 확인·하루 5회 차감(`tp_ai_claim`) → DB 사실 JSON(`tp_ai_facts`) → Claude → 저장(`tp_ai_save`), 실패 시 횟수 복구. 이 4개 함수는 화면에서 직접 부를 수 없습니다 |

### 외부 시스템 연동 지점 (확장 구조)

과제 범위(실시간 IoT·MES 연동 제외)에 따라 실제 연결은 하지 않았습니다. 대신 연결할 **입구**를 서버에 만들어 두었습니다.

| 외부 시스템 | 들어오는 입구 | 지금 시연에서 대신하는 것 |
|---|---|---|
| 설비 PLC·IoT 게이트웨이 | `POST /rest/v1/rpc/tp_ingest_signal` | 설비 상태 화면의 가상 설비 신호(수동·자동 재생) |
| MES·ERP 실적 | `tp_import_progress` (엑셀·CSV) | 작업 관리의 실적 가져오기 |
| 3D 뷰어(향후) | 같은 `tp_` 테이블을 읽기만 하면 됨 | 2D 공정 흐름(관제 대시보드) |

게이트웨이에서 신호를 보내는 예시(시연 코드는 단톡방 공유값):

```bash
curl -X POST "https://rrgvqgphhwzkeuvdwndu.supabase.co/rest/v1/rpc/tp_ingest_signal" \
  -H "apikey: <anon 키>" -H "Authorization: Bearer <anon 키>" -H "Content-Type: application/json" \
  -H "x-demo-code: <시연 코드>" \
  -d '{"p_eq":"EQ05","p_signal":"COUNT","p_value":30}'
```

### 지표 계산식

| 지표 | 계산 |
|---|---|
| 점유율 | RUNNING 시간 ÷ 운영시간. 운영시간 = 09/07 08:00 ~ 시연 시각, 매일 08~16시만. 기준시점에서는 9일 × 8h + 4h = 76h (EQ03 30.5h ÷ 76h = 40.1%) |
| 진행률 | 인정수량 ÷ 계획수량 |
| 기준일 계획 완료 | 09/16 시작 작업지시 중 완료 수 ÷ 6 |
| 계획 종료시각 도래·미완료 | 계획 종료 ≤ 시연 시각이면서 완료가 아닌 작업지시 |
| 기한 도래 작업 완료 | 계획 종료 ≤ 시연 시각인 작업 중 완료 수 ÷ 그 전체 수 |
| 납기 준수율 | 이송 완료 블록 중 실제 이송 완료 ≤ 목표 이송시각 |
| 검사 합격률 | PASS 차수 ÷ 전체 검사 차수 (불합격 0건인 차수 = 합격) |
| 공정별 계획 대비 실적 | 계획 종료 ≤ 시연 시각 작업의 Σ인정수량 ÷ Σ계획수량, 공정별 자기 단위 안에서만 합산 |

### 보안

- 화면(anon 키)은 `tp_` 테이블을 **읽기만** 할 수 있습니다(RLS). INSERT/UPDATE/DELETE 권한은 없습니다.
- 내부용 함수(`tp_reset_core`, `tp_load_seed`, `tp_set_eq_status` 등)는 화면에서 호출할 수 없습니다.
- 초기화는 전체 삭제가 아니라 시연 중 생긴 행(출처 demo, 12:00 이후 조치·기록, 원본에 없는 설비 구간)만 지우고 원본 행의 값을 엑셀 값으로 되돌립니다.
- 상태 변경은 서버 함수로만 가능하고, 모든 서버 함수는 요청 헤더 `x-demo-code`의 시연 코드가 맞아야 실행됩니다. 코드는 DB에 SHA-256 해시로만 저장됩니다.
- 서버 함수는 `search_path`가 고정되어 있습니다.
- AI 사용량 차감·결과 저장 함수는 Edge Function(service_role)만 호출할 수 있어, 시연 코드를 알아도 횟수를 되돌리거나 요약을 직접 써 넣을 수 없습니다.
- 시연 코드를 바꾸려면 SQL Editor에서 실행합니다:
  `update tp_config set value = encode(sha256(convert_to('새코드', 'UTF8')), 'hex') where key = 'demo_code_sha256';`

## 5. 서버 새로 설치하기 (팀원이 자기 Supabase에 올릴 때)

1. https://supabase.com 에서 새 프로젝트를 만듭니다(무료 플랜 가능).
2. 왼쪽 메뉴 **SQL Editor** → New query → `supabase_setup.sql` 내용 전체를 붙여 넣고 **Run**. (확장 기능까지 들어 있습니다)
   - 끝에 `{"ok": true, "msg": "09/16 12:00 원본 데이터로 초기화했습니다."}`가 나오면 성공입니다.
   - 이 파일에 든 시연 코드 해시는 현재 배포 코드입니다. 새 프로젝트에서는 위 4장의 update 문으로 반드시 새 코드로 바꾸세요.
3. **Project Settings → API**에서 Project URL과 `anon` `public` 키를 복사합니다.
4. `twinpro.html`을 열고 연결 설정 화면에 붙여 넣습니다.
5. AI 요약을 쓰려면 Edge Function을 배포합니다: Supabase CLI 설치 후 `supabase functions deploy tp-ai-summary --project-ref <프로젝트 ID>` → 2-1의 API 키 등록.
