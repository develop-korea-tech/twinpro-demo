## 2. 장면별 의도

- 전체·평면: 상태를 패널 숫자로 읽지 않고 공간에서 바로 본다. 색만으로 구분하지 않도록 기호를 함께 쓴다(▶ 작업 중, ■ 고장, ‖ 대기·보류, ✓ 끝남).
- 사건 현장: 원인(고장 설비), 영향(멈춘 블록), 대안(대체 후보)을 같은 화면에 번호로 보여 준다.
- 절차: 수요기업 DXE Manual처럼 "단계 + 자막 + 근거" 형식이다. 버튼은 화면 연출이 아니라 서버 규칙 함수 호출이다.
- 기록: 버튼을 누를 때마다 처리 기록에 시각과 내용이 남는다. 보고서를 따로 쓰지 않아도 된다.

## 4. 예상 질문

| 질문 | 답 |
|---|---|
| 실시간 연동인가 | 아니다. 제공 엑셀 데이터를 DB에 넣은 시연이다. 같은 구조에 실측 신호를 넣는 입구(신호 수신 함수)는 설비 상태 화면에 있다 |
| 3D는 과제 범위 밖 아닌가 | 과제 정의서상 3D는 제외 범위다. 2D 관제·작업 관리·기준정보가 본체이고, 3D는 수요기업 방향에 맞춰 시연용으로 확장했다(센터 확인) |
| AI는 무엇을 하나 | 서버 DB의 현재 값만 읽어 운영 요약 문장을 만든다. 원인을 단정하지 않는다. 하루 5회로 제한한다 |
| 대체 설비는 누가 정하나 | 시스템은 후보와 적합성 기준(용접 절차·출력·자격·위치)을 보여 주고, 승인은 생산관리 담당이 한다 |
